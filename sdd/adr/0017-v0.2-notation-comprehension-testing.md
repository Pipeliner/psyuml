# ADR-0017: v0.2 M14 — notation comprehension testing (Tier-A harness now, Tier-B as the honest gate)

- **Status:** accepted
- **Date:** 2026-06-16
- **Deciders:** project owner + maintainer
- **Spec / REQ touched:** v0.2 §5 / REQ-NOTATION-TESTING, REQ-EVAL-SUITE (extends ADR-0014)

## Context
v0.2 §5 makes **comprehension testing a release gate**: design symbols *with* novices, then
**comprehension-test them (ISO 9186, ≥67% general / ≥85% safety-critical) before freezing the asset
library**. The deep-research synthesis (§4) was decisive that a validated method exists and that
participatory generation + pre-freeze testing is the right discipline.

The hard, honest constraint: **a comprehension result requires real human participants.** The
project's whole stance is humility — it must **not** fabricate ≥67%/≥85% numbers, and an LLM
role-play is explicitly *not* a sample (the existing instruments banner says so). The spec itself
scopes this: "v0.2 ships the **protocol and a Tier-A harness**, and treats the **Tier-B studies as
the v1.0 gate** (real participants required)." Much of the human-study infrastructure already exists
(`docs/adoption/comprehension-instruments.md` Instruments A/B/C + pilot design; `docs/evaluation-
suite.md` gate + status), but it was **formulation-level** and predated the spec's symbol-level
ISO 9186 method — and there was **no enumerated symbol set** and **no automatable pre-study gate** in
code.

## Decision
Implement the half of §5 that can be honestly built now, and wire the rest as an explicit, recorded
**pending gate** — never faked.

1. **A symbol registry in code** — `NOTATION_SYMBOLS` (`@psyuml/profiles`): the closed, checkable set
   of symbols a client/picture reader must understand (core glyphs, connectors incl. the
   safety-critical **exit/way-out**, parts markers, the CAT trap/dilemma/snag marks), each with a
   plain gloss, its glyph, a dual-coding `redundantWord`, `safetyCritical`, tier, role. This makes
   "every picture-profile symbol" enumerable — the thing a study targets and the ledger lists.
2. **A Tier-A audit harness** — `auditNotation()` (`@psyuml/profiles`), enforced in CI via the
   profiles test. It does **not** measure comprehension; it enforces the *necessary conditions* a set
   must meet to be worth testing: **discriminability** (no shared glyph), **dual-coding** of
   safety-critical symbols (a redundant word — never glyph/colour-alone, §D), and a **gloss + unique
   id** per symbol. Mirrors `validateProfile`'s issue/`ok` shape.
3. **The Tier-B protocol + a per-symbol ledger (docs)** — `comprehension-instruments.md` gains
   **Instrument D (ISO 9186 per-symbol)** with the §5 thresholds + the wrong/opposite-meaning rule +
   participatory generation, and a **symbol ledger whose every Tier-B cell is `pending`** (Tier-A
   `pass`). `evaluation-suite.md` dimension 1, the v1.0 gate, and the status snapshot are updated to
   require the symbol-level bar and to credit the automated harness.

## Consequences
- **Positive:** the asset library now has an enumerated, CI-audited symbol set; safety-critical
  symbols are provably dual-coded before any human test; the §5 method (ISO 9186, per-symbol) is
  written down and tied to the gate; the ledger is the honest record that *will* hold evidence. The
  project keeps its integrity — the machinery and the gate ship; the **evidence does not** until real
  studies run.
- **Negative / cost:** the registry is **hand-curated** and can drift from the renderers (a glyph
  could change in `@psyuml/render` without the registry noticing) — mitigated by keeping it small and
  citing the canonical cheatsheet; a future cross-check test could bind them. Tier-A is a *necessary,
  not sufficient* condition — passing it says nothing about whether people understand a symbol. The
  CAT topology marks remain **untested placeholders**. Leaving v0.x stays **blocked** on Tier-B (this
  is the point, not a regression).
- **Impact:** `packages/profiles/index.ts` (+ test); `docs/adoption/comprehension-instruments.md`,
  `docs/evaluation-suite.md`; traceability REQ-NOTATION-TESTING (planned → in-progress: Tier-A
  landed). See `packages/profiles/IMPACT.md`, `docs/adoption/IMPACT.md`.

## Alternatives considered
- **Run a simulated / LLM comprehension study and record the numbers.** Rejected outright — it would
  be fabricated evidence and violate the §L.2 honesty stance; an LLM over-reads structured text and
  carries no comprehension load. The ledger stays `pending`.
- **Put the harness in `@psyuml/validate`** (spec §8 says validate *may*). Deferred — validate is
  model-only today; the registry + audit are about the *symbol library*, which `@psyuml/profiles`
  already owns (`CORE_TIER1_GLYPHS`, `StereotypeDef` glyph/nonColor/synonym checks). No sibling edge.
- **Auto-generate the registry from the renderers.** Rejected for now — the renderers draw shapes
  imperatively (no symbol table to read); a curated registry + cheatsheet citation is clearer, with a
  binding cross-check left as future work.
