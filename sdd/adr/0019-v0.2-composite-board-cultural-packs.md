# ADR-0019: v0.2 M16 — the Composite board + cultural-extension packs

- **Status:** accepted
- **Date:** 2026-06-16
- **Deciders:** project owner + maintainer
- **Spec / REQ touched:** v0.2 §2, §6, §K / REQ-DIAGRAM-FAMILIES, REQ-EXTENSION-MECH (extends ADR-0014; closes the v0.2 roadmap)

## Context
M16 is the last v0.2 milestone, with two unrelated deliverables:

1. **The Composite family** (spec §2: "one case across several views" / "synchronized sub-maps") was
   named in the families taxonomy (M11) but had **no renderer** — it is the only family with no
   concrete output. v0.1 already lets diagrams share node ids (§H.10 cross-diagram navigation); what
   was missing is a view that *arranges several member views of one case and surfaces those shared
   ids*.
2. **Cultural-permission** (spec §6 MUST): "any symbol/rite from a closed, initiatory, or
   culturally-restricted tradition MUST carry a permission/attribution declaration and MUST NOT be
   offered as a generic reusable icon." The §K profile mechanism (`ExtensionProfile`/`validateProfile`,
   ADR-0009) had no field or check for this.

Constraints: additive / backward-compatible (no Tier-1 core change, no model-schema break); reuse
the existing `render()` dispatcher and `validateProfile` rather than new machinery.

## Decision
1. **`renderComposite(models, options)` + `sharedNodeIds(models)`** in `@psyuml/render`. The board
   renders each member through the **`render()` dispatcher** (so the audience profile applies) and
   nests it as a scaled sub-`<svg>` in a titled panel, over a **shared-threads index** — the node ids
   present in ≥2 views, each tagged `data-shared-id` (and panels `data-composite-panel`) for
   cross-navigation. It takes an **array of models** (a case file), not a new model-schema type — so
   nothing in the core changes; `'composite'` stays metadata in the families registry.
2. **A `cultural` block on `StereotypeDef`** (`tradition`, `restricted`, `permission`, `attribution`)
   and a **`validateProfile` rule**: a `restricted` symbol with no `permission` is a
   `profile.cultural-permission` **error**; a restricted symbol *with* permission surfaces a
   `profile.cultural-restricted` **info** ("not a generic reusable icon"). A worked
   `CULTURAL_PACK_EXAMPLE` ships as the template (lints clean); `psyuml lint-profile` enforces the
   rule with no CLI change.

## Consequences
- **Positive:** the Composite family now has real output and a working cross-navigation key, reusing
  every renderer + the audience profile for free; the §6 cultural-permission MUST is enforced
  mechanically (not just prose), and a respectful worked pack shows the pattern. Both are additive —
  no Tier-1 change, no schema break, no golden churn (composite isn't in the golden corpus; the
  `cultural` field is optional).
- **Negative / cost:** nesting member SVGs means **duplicate `<marker id="arrow">` defs** across
  panels in one document — invalid-strictly but harmless in practice (the defs are identical and the
  first wins); a future pass could namespace them. The board is **render-only** — the editor does not
  yet build/show composites (one model at a time); that is future UI on top of this. The
  cultural-restriction check is a *declaration* check (permission present), not verification that
  permission was actually granted — it cannot be; it makes the obligation explicit and auditable.
- **Impact:** `packages/render/index.ts` (+ test), `packages/profiles/index.ts` (+ test); traceability
  REQ-COMPOSITE-BOARD + REQ-CULTURAL-PERMISSION (new, in-progress); ROADMAP M16. See
  `packages/render/IMPACT.md`, `packages/profiles/IMPACT.md`.

## Alternatives considered
- **A new `composite` model/diagram type holding sub-models.** Rejected — it would change the
  one-model core and break "profiles/views don't change the model"; a board over an *array* of
  existing models is additive and keeps each member a normal, valid model.
- **Re-render member content into the board's coordinate system (a `<g transform>` instead of a
  nested `<svg>`).** Rejected — that needs manual scaling math per member and re-tagging; a nested
  `<svg viewBox>` scales correctly for free (the duplicate-marker nit is the accepted trade).
- **A separate top-level `culturalRestriction` registry instead of a field on the stereotype.**
  Rejected — the restriction belongs *with* the symbol it governs, so `validateProfile` sees both
  together and `lint-profile` enforces it at the point of definition.
