# ADR-0018: v0.2 M15 — a lossy, export-only FHIR bridge (`@psyuml/interop`)

- **Status:** accepted
- **Date:** 2026-06-16
- **Deciders:** project owner + maintainer
- **Spec / REQ touched:** v0.2 §7, §6 / REQ-INTEROP-FHIR, REQ-PRIVACY (extends ADR-0014; realizes the long-shelved REQ-INTEROP-FHIR)

## Context
REQ-INTEROP-FHIR has been **planned and deliberately shelved** since M9 (regulation-sensitive,
late, optional). The v0.2 deep-research synthesis re-opened it with a concrete, honest finding
(§7): **FHIR has no native formulation or genogram resource**, so the only faithful move is a
**lossy, document-shaped export** — never a round-trip source of truth. The spec §7 table fixes the
mapping (Composition / ClinicalImpression / Observation / FamilyMemberHistory+List / CarePlan+Goal)
and **requires the limits to be documented**. Privacy is non-negotiable (§6, REQ-PRIVACY): exports
are audience-scoped and de-identified by default.

Constraints: the repo is dependency-light (zod only); a full FHIR SDK/validator would be heavy and
over-claim conformance. `@psyuml/privacy` already provides `deidentify` + `scopeToLayer`.

## Decision
Add **`@psyuml/interop`** — an **isolated leaf** package (spec §8: nothing depends on it but the
optional CLI subcommand) — exporting:

1. **`toFhir(model, options)` → a FHIR R4 *document* Bundle**, mapping per the §7 table: internal
   nodes → **Observation** (never **Condition** — PsyUML asserts nothing nosological, §A.3; node
   kind rides an `Observation.category` text, not a native type); interventions/resources →
   **CarePlan + Goal**; relational people → **FamilyMemberHistory + List**; the whole formulation →
   **Composition** (document root) + **ClinicalImpression** (the closest native match, fixing **no**
   diagnosis). **De-identified + audience-scoped by default** (reuses `@psyuml/privacy`).
2. **A structured `loss` report** alongside the bundle (`roundTrip: false` + an item per dropped
   construct: relational edge semantics, loop topology, bands/phases, provenance/confidence/standing,
   ritual framing, triggers, "node typing lives in an extension"). This is the §7 "limits MUST be
   documented" made executable, not prose.
3. **`validateFhirBundle`** — a zod **subset** schema (required fields per emitted resource +
   intra-bundle reference integrity), **explicitly not** a full FHIR validator. The CLI sanity-checks
   its own output with it before emitting.
4. **No importer.** There is deliberately no `fromFhir`; the export is one-way and the diagram stays
   canonical.
5. A **`psyuml export`** CLI subcommand (`--scope`, `--no-deidentify`, `--term`, `-o`) that prints the
   bundle to stdout and the loss report + consent warning to stderr.

## Consequences
- **Positive:** PsyUML content can enter a record through a standard format **honestly** — the loss is
  enumerated, not hidden; non-diagnostic and de-identified by default; dependency-free; isolated
  (removing it changes nothing else). The long-shelved REQ-INTEROP-FHIR is realized without pulling
  the project toward regulated CDS (it is export-only, documentation infrastructure).
- **Negative / cost:** `validateFhirBundle` proves conformance only to **the subset we emit** — a
  real FHIR server may demand more (terminologies/bindings, profiles, narrative xhtml rigor); we do
  not claim full R4 conformance. The genogram mapping is the lossiest (edge semantics gone) — by
  nature, and flagged. The narrative summary is generated, not the rendered diagram. SNOMED/LOINC
  coding is left as `CodeableConcept.text` only (no terminology binding yet).
- **Impact:** new `packages/interop/` (+ test, IMPACT); `packages/cli/index.ts` (+ `export` subcommand,
  + dep, + test); `sdd/README.md` DAG (interop now present); traceability REQ-INTEROP-FHIR
  (planned → in-progress). See `packages/interop/IMPACT.md`, `packages/cli/IMPACT.md`.

## Alternatives considered
- **A lossless round-trip / `fromFhir`.** Rejected (and spec §7 forbids it) — FHIR can't carry
  genogram edge semantics or PsyUML's typed graph; a round-trip would silently corrupt meaning.
- **Map symptoms/nodes to `Condition`.** Rejected — that asserts diagnosis; PsyUML is non-diagnostic
  (§A.3). `Observation` (+ `ClinicalImpression` summary) is the honest target.
- **Depend on a FHIR SDK / full validator.** Rejected — heavy, and it would imply a conformance claim
  we don't make; a zod subset + reference-integrity check is proportionate and honest.
- **Bind SNOMED/LOINC codes now.** Deferred — terminology binding is a large, separate effort; text
  CodeableConcepts are the honest placeholder, noted as loss.
